# סקירת הקורס — C# Programming in the .NET Framework: הכשרה מעשית מעודכנת

ברוכים הבאים! מסמך זה מסביר למי הקורס מיועד, מה נלמד בכל יום, איך בנויים חומרי הקורס ואיך להפיק מהם את המרב.

## למי הקורס מיועד

- מפתחים בתחילת הדרך (Junior) שרוצים ללמוד C# ו-.NET בצורה מסודרת ומעשית.
- מפתחים משפות אחרות (Java, Python, JavaScript, C++) שעוברים ל-.NET.
- מי שכתב C# "פעם" ורוצה להתעדכן: .NET 10, C# מודרני, async, WPF וכלי AI.

## דרישות קדם

- ידע בסיסי בתכנות באיזושהי שפה: משתנים, תנאים, לולאות, פונקציות. לא נדרש ידע קודם ב-C#.
- היכרות בסיסית עם שורת פקודה ועם Git (clone, commit) — יתרון, לא חובה.
- **מחשב עם סביבת עבודה מותקנת** לפי `00-Setup/INSTALL.md`. ליום 3 (WPF) נדרש Windows. הריצו את `00-Setup/VerifySetup` לפני היום הראשון.
- חשבונות לכלי AI ליום 4 (GitHub Copilot, Claude, ChatGPT) — פתחו מראש.

## מפת הקורס — ארבעה ימים

### יום 1 — OOP, Collections, Exception Handling
נתחיל מהיסודות של השפה ושל ה-.NET: מבנה פרויקט, טיפוסים, מחרוזות, ואז נצלול לתכנות מונחה-עצמים ב-C# — מחלקות, מאפיינים, ירושה, ממשקים, מחלקות אבסטרקטיות, records ופולימורפיזם. נלמד את האוספים המרכזיים (`List<T>`, `Dictionary<K,V>`, `HashSet<T>` ועוד), מתי לבחור כל אחד, ואיך לעבד אותם עם LINQ. נסיים בטיפול בחריגות: try/catch/finally, חריגות מותאמות אישית, וכללי "מתי לתפוס ומתי לזרוק". בסוף היום תדעו לבנות מודל דומיין קטן, נקי ובטוח.

### יום 2 — Multithreading, Async, APIs (REST + JSON)
נבין מה ההבדל בין thread, task ו-async, מתי כל אחד מתאים ואיך להימנע מהמלכודות הקלאסיות (deadlocks, race conditions, חסימת ה-UI). נעבוד עם `Task`, `async`/`await`, `Task.WhenAll`, `CancellationToken` ואוספים בטוחים ל-threads. בחלק השני נתחבר לעולם: נקרא ל-REST APIs עם `HttpClient`, נפרסר JSON עם `System.Text.Json`, נטפל בשגיאות רשת ו-timeouts, ונבנה לקוח API מלא ואסינכרוני.

### יום 3 — Rapid GUI Development (WPF, עם השוואה ל-WinForms)
יום של בניית ממשקי משתמש ב-Windows. נכיר את WPF: XAML, פריסות (Grid, StackPanel), פקדים, אירועים, Data Binding, `INotifyPropertyChanged`, `ObservableCollection`, ותבנית MVVM בגרסה פרקטית. נראה איך לחבר את ה-UI לקוד האסינכרוני מיום 2 בלי לתקוע את החלון. לאורך היום נשווה ל-Windows Forms — מתי הוא עדיין בחירה סבירה ומה ההבדלים במודל התכנות — כדי שתוכלו לבחור נכון בפרויקטים שלכם.

### יום 4 — AI-Assisted Development and Maintainable Code
היום האחרון מחבר הכול לעבודה מקצועית. נלמד לכתוב קוד תחזוקתי: עקרונות SOLID בגרסה מעשית, refactoring, בדיקות יחידה עם xUnit, dependency injection ולוגים. במקביל נשלב כלי AI בזרימת העבודה: GitHub Copilot להשלמות וצ'אט ב-IDE, Claude ו-Claude Code למשימות גדולות (הסבר קוד קיים, כתיבת בדיקות, refactoring מודרך), ChatGPT ו-Cursor — כולל איך לנסח בקשות טובות, איך לבקר תוצאות ומה לא למסור לכלים חיצוניים. הקורס מסתיים במפגש סיום על **כלי AI לפיתוח ממשקי משתמש**: יצירת XAML ומסכים בעזרת AI, וחיבור לחומר של יום 3.

## איך עובדים על מעבדה (Lab)

1. קראו את `README.md` של המעבדה עד הסוף לפני שמתחילים — במיוחד את קריטריוני הקבלה.
2. **העתיקו את תיקיית `Starter`** למקום העבודה שלכם (למשל `my-work/Lab1`) ועבדו על העותק. כך המקור נשאר נקי ואפשר להתחיל מחדש.

<div dir="ltr">

```bash
cp -r Day1-OOP-Collections-Exceptions/Labs/Lab1-Name/Starter my-work/Day1-Lab1
cd my-work/Day1-Lab1
dotnet run
```

</div>

3. עבדו שלב-שלב. אחרי כל שלב הריצו (`dotnet run` / `dotnet test`) — אל תכתבו 200 שורות ואז תקמפלו.
4. **אל תציצו ב-`Solution` לפני שניסיתם ברצינות.** נתקעתם? קודם הרמזים ב-README, אחר כך שאלה למרצה או לשכן, ורק אז הפתרון. מי שמעתיק פתרון לא לומד — מי שמשווה את הפתרון שלו לפתרון המוצע, לומד פעמיים.
5. סיימתם מוקדם? יש בונוס בכל מעבדה. אפשר גם לשפר: להוסיף בדיקות, לשפר שמות, לטפל במקרי קצה.
6. ביום 4 נעבוד עם כלי AI — במעבדות של ימים 1–3 עדיף לכתוב בעצמכם. המטרה היא להבין, לא לסיים.
